# ORGY M0 极简原型实现规范（Tracer Bullet - Rev 2）

**定位**：单用户、Windows 本机首发（架构兼容 Linux/macOS）、单任务端到端闭环（无并发合并队列、无复杂依赖图推导、无 PTY 接管）  
**目标代码量**：核心实现约 $1500 \sim 2500$ 行 Rust（不含测试，采用同步线程模型，不引入异步运行时）

---

## 1. M0 裁剪红线（做什么 vs 不做什么）

为了把认知负担降到最低，M0 遵循**“只做主路径，异常直接报错退出交给人”**的原则：

| 模块 | M0 极简实现（必做） | M0 明确砍掉（延后至 M1/M2） |
| :--- | :--- | :--- |
| **规范解析** | 直接读取纯 YAML 文件（`contracts.yaml`、`tasks/<id>.yaml`、`verification.yaml`）。 | 砍掉 Markdown 围栏代码块解析器、散文语气词扫描、墓碑列表、AI `drafts/` 提案目录。 |
| **状态与哈希** | SQLite 仅 3 张表（`tasks`、`attempts`、`receipts`）；仅保留 **3 个哈希**（见 §4）。 | 砍掉独立 `operations` 意图对账表、11 种细分 Digest、`audit.jsonl` 自动导出。 |
| **增量失效** | `spec_digest` **仅提取任务 `inputs` 显式声明条目的语义字段**与任务自身语义字段；Worktree 保留完整仓库但忽略未声明文件的偷看风险。 | 砍掉 Merkle 树递归滚动哈希、全库可读连坐失效、`public_digest` 早期截断、局部文件集复制检查。 |
| **进程执行** | 同步多线程模型（`std::thread`）+ Windows Job Object（关闭即强杀子进程树）+ 显式句柄白名单双管道排空 + `.orgy/outbox/handoff.json` 文件交付。 | 砍掉 Tokio 异步运行时、PTY 诊断兜底、JSON 结构自动修复轮（格式错直接算当前 Attempt 失败）、CLI 能力探针。 |
| **副作用与硬件** | **Worker 只写代码，禁止任何硬件副作用**；烧录与板级测试全部放进 `verification.yaml` 由 Supervisor 执行。 | 砍掉 Worker 交付物中的 `irreversible_actions` 字段及 `BLOCKED` 硬件授权流。 |
| **验证与对账** | 独立 `staging` worktree 检出候选提交 $\rightarrow$ 跑测试命令 $\rightarrow$ 用 `git status --porcelain --untracked-files=normal` 检测可观察到的工作区污染。 | 砍掉自研前后全文件 SHA-256 扫描对比、砍掉 `requested_dependencies` 自动预取、砍掉 `integration_group` 三方合并。 |

## 2. 目录结构、Git 引用与前置安全护栏

M0 不接管人类当前检出的 Git 分支，所有机器状态收敛在 `.orgy/runtime/` 与专属 Git refs 下：

```text
<repo_root>/
├── .orgy/
│   ├── spec/                          # [进 Git] 人类直接编辑的纯 YAML 规范
│   │   ├── contracts.yaml             # 假设与接口条目字典（统一复数命名）
│   │   ├── verification.yaml          # 受保护的验收计划与命令
│   │   └── tasks/
│   │       └── T-1.yaml               # 单个任务定义
│   └── runtime/                       # [加入 .gitignore] 仅 Supervisor 读写
│       ├── supervisor.lock            # OS 强制排他锁（Windows LockFileEx / Unix flock）
│       ├── state.db                   # SQLite 状态库（WAL 模式）
│       ├── logs/
│       │   └── T-1.a1.log             # 合并保存的 stdout/stderr 原始日志
│       └── worktrees/
│           ├── T-1/                   # Task 专属工作区（含 .orgy/outbox/）
│           └── staging/               # 独立干净验收工作区
```

* **受管 Git Refs**：
  * `refs/orgy/accepted`：已通过 L3 验收的基线提交（初始化时指向人类当前的 `HEAD`）。
  * `refs/orgy/attempts/<task_id>/<attempt_num>`：每次 Worker 退出后保存的现场快照提交。
* **两道强制安全护栏**：
  1. **初始化干净检查**：`orgy` 初始化 `refs/orgy/accepted` 时，必须确认人类主工作区 `git status --porcelain`（除 `.orgy/` 外）为空，防止任务 worktree 丢失人类未提交的本地修改。
  2. **破坏性命令路径锁**：代码中任何执行 `git reset --hard` 或 `git clean -fdx` 的函数，必须先校验目标目录的 canonical path 严格位于 `.orgy/runtime/worktrees/` 之下，严禁作用于人类主工作区。

## 3. 配置文件与交付协议（极简 Schema）

### 3.1 契约与假设文件（`.orgy/spec/contracts.yaml`）

合并假设与接口，计算哈希时只提取语义字段，显式忽略 `note` 字段：

```yaml
entries:
  A-1:
    kind: assumption
    value_type: integer
    value: 115200
    note: "UART2 波特率，与模组出厂固件一致（修改此字段不触发重算）"

  IF-1:
    kind: interface
    sig: "int uart_read(uint8_t *buf, size_t len)"
    invariants:
      - "非阻塞，成功返回读取字节数，错误返回负值"
    note: "底层驱动接口"
```

### 3.2 任务定义文件（`.orgy/spec/tasks/T-1.yaml`）

```yaml
id: T-1
title: "UART 环形缓冲区读取"            # 仅供展示，不计入 spec_digest
objective: "实现 UART 环形缓冲区读取逻辑并通过单元测试"
cli_profile: "codex"                   # 对应本地配置的 CLI 适配器
max_attempts: 3
timeout_sec: 600
inputs:                                # 仅计算此列表内条目的语义投影哈希
  - A-1
  - IF-1
writes:                                # 允许修改的精确相对路径或组件级 Glob（如 src/uart/**）
  - "src/uart.c"
  - "include/uart.h"
  - "tests/test_uart.c"
verification_plan: "uart-unit-test"
note: "探索期实现，暂不考虑 DMA"         # 忽略字段，不计入 spec_digest
```

### 3.3 验证计划文件（`.orgy/spec/verification.yaml`）

硬件烧录或板级测试直接作为验证步骤配置在此处，由 Supervisor 在持有本地锁时弹窗确认执行：

```yaml
plans:
  uart-unit-test:
    resources: []                      # 如需硬件则填 ["hw:board-1"]
    steps:
      - name: "build_and_test"
        argv: ["cargo", "test", "--frozen", "-p", "uart"]
        timeout_sec: 120
        requires_human_confirm: false  # 若为 JTAG 烧录命令则设为 true
```

### 3.4 Worker 交付物协议（`.orgy/outbox/handoff.json`）

Prompt 中要求 CLI 结束前将以下 JSON 写入工作区下的 `.orgy/outbox/handoff.json`（不入 Git）：

```json
{
  "task_id": "T-1",
  "attempt": 1,
  "status": "COMPLETED",
  "summary": "已实现环形缓冲区读取与边界测试",
  "files_changed": ["src/uart.c", "tests/test_uart.c"],
  "questions": []
}
```
* `status` 仅允许：`COMPLETED` | `BLOCKED` | `NEEDS_CLARIFICATION`。
* **跨字段约束**：当 `status == COMPLETED` 时，`questions` 必须为空数组；当 `status == NEEDS_CLARIFICATION` 时，`questions` 必须非空。
* **不采信自报文件列表**：`files_changed` 仅用于与实际 Git diff 交叉比对（若 Worker 漏报或谎报修改文件，记为 `CLAIM_MISMATCH`），**绝不作为写集授权依据**。

## 4. 语义投影、SQLite 核心表与 Fresh 判定

### 4.1 消除拼接歧义的语义投影哈希（3 个核心指纹）

严禁直接拼接多个 JSON 字符串计算哈希。统一在 Rust 中构造确定性投影结构体（使用 `BTreeMap` 保证键名按 UTF-8 字典序排列，显式剔除 `note`、`title` 等非语义字段），序列化为单一 Canonical JSON 字节流后计算 SHA-256：

1. **`spec_digest`**：
   ```json
   {
     "version": "orgy-spec-v1",
     "task": {
       "id": "T-1",
       "objective": "实现 UART 环形缓冲区读取逻辑并通过单元测试",
       "inputs": ["A-1", "IF-1"],
       "writes": ["include/uart.h", "src/uart.c", "tests/test_uart.c"],
       "verification_plan": "uart-unit-test"
     },
     "entries": {
       "A-1": { "kind": "assumption", "value_type": "integer", "value": 115200 },
       "IF-1": { "kind": "interface", "sig": "int uart_read(uint8_t *buf, size_t len)", "invariants": ["..."] }
     }
   }
   ```
2. **`plan_digest`**：对 `verification.yaml` 中目标 plan 的 `{ "version": "orgy-plan-v1", "resources": [...], "steps": [...] }` 序列化计算 SHA-256。
3. **`candidate_commit`**：Worker 产出的代码快照 Git Commit SHA。

### 4.2 初始化 SQL（3 张表）

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=FULL;
PRAGMA foreign_keys=ON;

CREATE TABLE tasks (
    task_id          TEXT PRIMARY KEY,
    status           TEXT NOT NULL, -- PENDING, RUNNING, RETRYING, COMPLETED, BLOCKED, PAUSED_FOR_HUMAN, FAILED
    spec_digest      TEXT NOT NULL,
    plan_digest      TEXT NOT NULL,
    accepted_commit  TEXT,          -- 最近一次通过验证并晋升的 commit
    updated_at       INTEGER NOT NULL
);

CREATE TABLE attempts (
    attempt_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id          TEXT NOT NULL REFERENCES tasks(task_id),
    attempt_num      INTEGER NOT NULL,
    base_commit      TEXT NOT NULL, -- 启动时的 refs/orgy/accepted
     start_spec_digest TEXT NOT NULL, -- 启动时的 spec_digest（防运行期被改）
    start_plan_digest TEXT NOT NULL, -- 启动时的 plan_digest（防运行期被改）
    snapshot_commit  TEXT,          -- 退出后打包的 refs/orgy/attempts/<id>/<n>
    exit_code        INTEGER,
    l2_status        TEXT,          -- COMPLETED / BLOCKED / NEEDS_CLARIFICATION
    verdict          TEXT NOT NULL, -- PASSED / SCOPE_VIOLATION / CLAIM_MISMATCH / VALIDATION_FAILED / PROTOCOL_ANOMALY / TIMEOUT / STALE_ABORTED / BLOCKED / NEEDS_CLARIFICATION
    error_detail     TEXT,          -- 注入给下一次重试的精简错误原因
    log_path         TEXT NOT NULL,
    created_at       INTEGER NOT NULL,
    UNIQUE(task_id, attempt_num)
);

CREATE TABLE receipts (
    receipt_id       INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id          TEXT NOT NULL REFERENCES tasks(task_id),
    parent_commit    TEXT NOT NULL, -- 该候选基于的 base_commit（用于崩溃恢复对账）
    candidate_commit TEXT NOT NULL,
    spec_digest      TEXT NOT NULL,
    plan_digest      TEXT NOT NULL,
    passed           INTEGER NOT NULL, -- 1 为通过，0 为失败
    created_at       INTEGER NOT NULL
);
```

### 4.3 新鲜度（FRESH）判定规则（兼容多任务串行推进）

查询 `receipts` 表中该任务最新一条 `passed = 1` 的记录，当且仅当同时满足以下 **4 个条件**时，判定该任务为 `FRESH`，直接跳过执行：
1. `receipt.spec_digest == current_spec_digest`
2. `receipt.plan_digest == current_plan_digest`
3. `receipt.candidate_commit` 是当前 `refs/orgy/accepted` 的祖先提交或本身（即 `git merge-base --is-ancestor <candidate_commit> refs/orgy/accepted` 返回 0，防止人为回滚 `accepted` 分支后误用旧收据）；
4. 从 `<candidate_commit>` 到当前 `refs/orgy/accepted` 之间，该任务的写集路径未被后续其他任务修改过（即 `git diff --quiet <candidate_commit> refs/orgy/accepted -- <task.writes...>` 返回 0）。

## 5. 核心执行流程与状态转换表

### 5.1 启动崩溃自检（Git Ref 与 SQLite 跨存储对账）

由于 `git update-ref` 与 SQLite 事务无法做到跨引擎原子提交，每次 `orgy` 进程启动并获取 `supervisor.lock` 后，**必须先执行崩溃恢复对账**，再响应用户命令：
1. 读取当前 `refs/orgy/accepted` 的 commit SHA（记为 $R_{\text{git}}$），并校验该 commit 对象在 Git 库中真实存在。
2. 查询 SQLite `receipts` 表中最新一条 `passed = 1` 的记录（记其候选提交为 $C_{\text{db}}$，其父提交为 $P_{\text{db}}$）：
   * **情况 A（正常一致）**：若无记录，或 $R_{\text{git}} == C_{\text{db}}$，对账通过，继续运行。
   * **情况 B（上次写完 SQLite 后、更新 Git ref 前崩溃）**：若 $R_{\text{git}} == P_{\text{db}}$，且 $C_{\text{db}}$ 对象存在，立即幂等补做一次 `git update-ref refs/orgy/accepted <C_db> <P_db>`，修复完成。
   * **情况 C（未知状态/人为篡改）**：其余任何不匹配情况，立即报错并暂停运行（绝不自动重试或覆盖），提示人工核查。

### 5.2 单任务主循环（`orgy run T-1`）

```text
[0. 启动崩溃对账] ──(状态矛盾)──> 报错退出，等待人工核查
       │
[1. 哈希计算与 Fresh 检查] ──(满足 §4.3 四个条件)──> 已是 FRESH，直接退出
       │
[2. 准备 Task Worktree] (记录 start_spec/plan_digest 与 base_commit，重置工作区)
       │
[3. 组装 Prompt 并启动 CLI] (Windows Job + 显式句柄白名单 + 同步双线程排空管道)
       │
[4. 采集快照与 L1/L2/写集校验] ──(越界/非零退出/协议错)──> 按 §5.3 状态表流转
       │
[5. Staging 独立验收 (L3)] ──(测试失败/工作区污染)──> 按 §5.3 状态表流转
       │
[6. 晋升前防漂移复核] ──(规范或 accepted 基线已变)──> 记 STALE_ABORTED，不晋升
       │
[7. 先提交 SQLite Receipt，再更新 refs/orgy/accepted] ──> 任务 COMPLETED
```

### 5.3 Attempt 结局与 `max_attempts` 状态转换表

每次 Attempt 均计入 `attempt_num`（从 $1$ 递增至 `max_attempts`）：

| Attempt 判定结局 (`verdict`) | 触发条件 | 是否允许自动重试 | Task 终态流转（当 `attempt_num == max_attempts` 时） |
| :--- | :--- | :--- | :--- |
| **`PASSED`** | L1 退出码为 0 ∧ L2 为 `COMPLETED` ∧ 写集与自报文件合规 ∧ L3 验证全过 ∧ 晋升前复核无漂移 | 无需重试 | 立即设为 `COMPLETED` 并退出循环 |
| **`SCOPE_VIOLATION`** | 实际 Git 变更超出 `writes` 白名单、包含 `.orgy/`、含符号链接或非法路径 | **是**（重置回 `base_commit`） | 未超限则 `RETRYING`；耗尽额度则设为 **`FAILED`** |
| **`CLAIM_MISMATCH`** | `handoff.json` 的 `files_changed` 与实际 Git diff 文件集合不一致 | **是**（保留代码现场） | 未超限则 `RETRYING`；耗尽额度则设为 **`FAILED`** |
| **`PROTOCOL_ANOMALY`** | L1 退出码非 0，或缺失/无法解析合法的 `handoff.json` | **是**（保留代码现场） | 未超限则 `RETRYING`；耗尽额度则设为 **`FAILED`** |
| **`TIMEOUT`** | 超过 `timeout_sec` 被 Job Object 强杀 | **是**（重置回 `base_commit`） | 未超限则 `RETRYING`；耗尽额度则设为 **`FAILED`** |
| **`VALIDATION_FAILED`** | Staging 测试命令返回非 0，或测试后 `git status` 发现工作区污染 | **是**（保留代码现场） | 未超限则 `RETRYING`；耗尽额度则设为 **`FAILED`** |
| **`BLOCKED`** | L1 为 0 且 L2 声明 `status == BLOCKED` | **否（立即暂停）** | 立即设为 **`BLOCKED`** 并退出，交由人工处理 |
| **`NEEDS_CLARIFICATION`** | L1 为 0 且 L2 声明 `status == NEEDS_CLARIFICATION` | **否（立即暂停）** | 立即设为 **`PAUSED_FOR_HUMAN`** 并打印 `questions` |
| **`STALE_ABORTED`** | 步骤 6 晋升前复核发现 YAML 规范或 `refs/orgy/accepted` 在运行期间被修改 | **否（立即中止）** | 设为 **`PENDING`**，保留快照 ref，提示用户重新运行 |

## 6. 关键工程实现细节（避坑指南）

### 6.1 步骤 3：Windows 进程启动、句柄隔离与同步双线程排空
1. **同步线程模型**：使用标准库 `std::process::Command` 与 `std::thread::scope`，不引入异步运行时。
2. **防止管道句柄泄漏死锁**：在 Windows 下创建管道后，使用 `InitializeProcThreadAttributeList` 与 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`，显式指定仅允许子进程继承当前 `stdin`、`stdout`、`stderr` 三个句柄，严禁裸用无过滤的句柄继承。
3. **Job Object 强绑定**：创建 Windows Job Object 并设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。使用 `CREATE_SUSPENDED` 启动 CLI，调用 `AssignProcessToJobObject` 成功后，再调用 `ResumeThread`。
4. **防阻塞排空**：主线程向 `stdin` 写入 Prompt 后立即 `drop(stdin)` 关闭写端；在 `thread::scope` 中派生两个线程分别持续读取 `stdout` 和 `stderr` 并写入日志文件（不能先 `wait` 再读管道，否则 stderr 写满 $64\text{ KB}$ 缓冲区会导致子进程死锁）。主线程循环 `try_wait` 检查超时，超时则直接关闭 Job Object 句柄连根强杀整棵进程树。

### 6.2 步骤 4：精确路径组件级写集校验（防前缀绕过与重命名逃逸）
1. 进程树确认退出后，先读取并移走 `.orgy/outbox/handoff.json`。
2. 在 `/worktrees/T-1` 中打包现场快照：
   ```bash
   git add -A
   git commit --allow-empty -m "orgy attempt snapshot"
   git update-ref refs/orgy/attempts/T-1/<n> HEAD
   ```
3. **使用 `-z` 与 `--name-status` 提取精确变更**：
   ```bash
   git diff --name-status -z <base_commit> refs/orgy/attempts/T-1/<n>
   ```
   以 `\0`（NUL）切分输出，解析所有变更路径（对于 `R` 重命名或 `C` 复制操作，**源路径与目标路径必须同时納入校验**；对于 `D` 删除操作，被删路径同样纳入校验）。
4. **按路径组件校验（严禁使用字符串 `starts_with`）**：
   * 拒绝任何包含 `..`、绝对路径、以 `.orgy` 开头、或工作区中 `symlink_metadata().file_type().is_symlink()` 为真的路径。
   * 将路径统一归一化为 `/` 分隔，按路径组件（Path Components）或 `globset` 精确匹配 `task.writes`。例如：若 `writes` 声明为 `src/uart.c`，绝不能匹配 `src/uart.c.evil`；若允许修改整个子目录，必须在 `writes` 中显式写为 `src/uart/**`。

### 6.3 步骤 5 & 6：Staging 污染检测与晋升前防漂移复核
1. **Staging 检出与测试**：
   ```bash
   git -C .orgy/runtime/worktrees/staging reset --hard <snapshot_commit>
   git -C .orgy/runtime/worktrees/staging clean -fdx
   ```
   执行 `verification.yaml` 中的命令（所有参数通过 `Command::args` 数组传递，严禁拼接 shell 字符串；将 `CARGO_TARGET_DIR` 指向 `.orgy/runtime/build_cache`）。
2. **检测可观察到的工作区污染**：
   测试命令返回 `0` 且进程树完全回收后，执行：
   ```bash
   git -C .orgy/runtime/worktrees/staging status --porcelain --untracked-files=normal
   ```
   若输出非空，判为 `VALIDATION_FAILED`。（注：此机制仅检测测试结束后残留的受跟踪文件篡改与未忽略的新增文件，不防御测试运行中篡改源码后又自行恢复的恶意脚本）。
3. **晋升前防漂移复核（防 TOCTOU）**：
   在写入 `receipts` 前，重新从磁盘读取 YAML 计算 `current_spec_digest`、`current_plan_digest`，并读取当前 `refs/orgy/accepted`。若与当前 Attempt 启动时记录的 `(start_spec_digest, start_plan_digest, base_commit)` 存在任何不一致，立即中止晋升，记录 `verdict = STALE_ABORTED`。
4. **两步法落盘晋升**：
   复核无误后，**第一步**提交 SQLite 事务（插入 `receipts` 并設 `tasks.status = COMPLETED`）；**第二步**执行 `git update-ref refs/orgy/accepted <snapshot_commit> <base_commit>`。

## 7. M0 Rust 模块划分与验收清单

### 7.1 推荐代码结构与依赖

```text
src/
  main.rs         // 程序入口与启动崩溃对账调用
  cli.rs          // clap 命令行定义 (init, run, status)
  config.rs       // YAML 反序列化与跨字段校验
  digest.rs       // BTreeMap 语义投影与 SHA-256 计算
  db.rs           // rusqlite 建表、事务与 Fresh 查询
  git.rs          // 受控 git 子进程封装、worktree 安全护栏、-z 写集校验、ref CAS
  process.rs      // Windows Job Object、显式句柄列表、同步双线程管道排空
  supervisor.rs   // 单任务 7 步状态机主循环
  error.rs        // thiserror 错误类型定义
```

* **推荐依赖（`Cargo.toml`）**：`clap`、`serde`、`serde_json`、`serde_yml`（或 `toml`）、`sha2`、`hex`、`globset`、`rusqlite (features = ["bundled"])`、`thiserror`、`windows-sys`（Win32 JobObjects / Threading / Foundation / Security / Storage_FileSystem）。

### 7.2 M0 必测验收场景（9 项）

1. **越界拦截**：Worker 修改 `writes` 之外的文件、删除未授权文件、重命名文件逃逸、或修改 `.orgy/spec/` 时，均被 `SCOPE_VIOLATION` 拦截并重置工作区。
2. **前缀绕过防御**：`writes` 允许 `src/uart.c` 时，Worker 创建 `src/uart.c.evil` 必须被判为 `SCOPE_VIOLATION`。
3. **孙进程强杀**：测试或 Worker 拉起死循环孙进程，超时后 Windows Job Object 能干净杀光整棵进程树，无残留句柄。
4. **管道防死锁**：子进程向 `stderr` 狂写超过 $1\text{ MB}$ 数据后退出，Supervisor 排空线程不发生阻塞死锁。
5. **语义投影与增量复用**：修改 `contracts.yaml` 中无关条目的 `value` 或目标条目的 `note` 时，已完成任务保持 `FRESH`；修改目标条目的 `value` 时，任务变为 `STALE` 并重跑。
6. **运行期规范防漂移**：在 Worker 运行期间手动修改 `T-1.yaml` 或 `verification.yaml` 并保存，本次运行结束后必须触发 `STALE_ABORTED`，拒绝晋升。
7. **重试熔断**：连续失败达到 `max_attempts` 后，任务状态稳定停在 `FAILED`，不再无限重试；返回 `BLOCKED` 或 `NEEDS_CLARIFICATION` 时立即暂停，不消耗后续重试次数。
8. **跨存储崩溃恢复**：模拟在 SQLite 写入 `receipt` 后、`git update-ref` 前强杀 Supervisor，下次启动时能自动将 `refs/orgy/accepted` 补齐到 `candidate_commit`。
9. **工作区污染拦截**：验证脚本在源码目录修改受跟踪文件或留下未忽略的野生文件，即便退出码为 `0`，也会被判为 `VALIDATION_FAILED`。
